第 8 章示意图 · 登录态不是三选一

Cookie、Session、Token 是不同层的零件，常常一起用

把它们当成三种「登录产品」去背，面试会直接说错。下面这叠蛋糕才接近真实系统。

你怎么认出「这是我」　Token / Session ID　——凭证或会话标识，可能是一串随机值，也可能是 JWT 这类自包含令牌
服务器是否记住这次登录　Session　——服务端会话状态。没有这一层时，服务器可能只验证 Token
浏览器如何保存并自动带上　Cookie　——一种存储和发送机制。Session ID 或 Token 都可以放进 Cookie
请求里怎么出示　例如 Authorization: Bearer … 或自动带上 Cookie。Bearer 只是出示方式，不是 Token 的别名

MiniShop v1.0：登录 JSON 里给 token，同时 Set-Cookie HttpOnly。后续 API 以 Bearer 为准。HttpOnly 挡住的是脚本读取，不是请求携带。

示意图：一层是「是什么」，一层是「存在哪」，一层是「怎么带出门」。不要说「我们只用 Cookie，所以没有 Token」。
