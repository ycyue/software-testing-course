## 专项审查

### 技术准确性

- GET/POST 语义与第 9 章一致，未写成加密神话；
- Cookie 与 Bearer 可同时存在，未写成三选一；
- 变量范围从宽到窄及同名覆盖与官方文档一致；
- Token 不放可分享初始值；
- 断言放在发送后（Tests / Post-response）；
- Runner 不能替代出口标准与 SQL 核对；
- 两次下单不同 id 表示不幂等，与第 13 章审查一致；
- 未声称接口自动化 ROI 永远最高。

### 脚本与 Collection 验证

用模拟 `pm` 对象执行正文含 `pm.test` 的脚本：

| 脚本 | 模拟响应 | 结果 |
| --- | --- | --- |
| 登录成功 | 200 `{result, token}` | 通过并 set `teach-token` |
| 登录失败 | 401 | 断言失败（符合预期） |
| 商品列表 | 200 `{items:[]}` | 通过 |
| 超库存 | 400 `{error}` | 通过 |
| 创建订单 | 201 `{id}` 无 status | 通过并 set `orderId` |
| 无凭证 | 401 | 通过 |

教学 Collection v2.1 JSON 可解析，含 7 个请求，schema 指向 Collection v2.1。未启动 Postman GUI。

### MiniShop 一致性

- `baseUrl`/`token`/路径均为教学约定；
- 不写订单状态名；
- 超库存与未认证覆盖第 13 章检查点。

### 安全

- 密码仅变量或本机当前值；
- 禁止公开 Workspace 分享生产 token；
- 导出脱敏。
