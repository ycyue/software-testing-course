# 第 7 章《Web 基础》质量审查记录

## 审查信息

- 审查对象：`chapters/07-web-basics.md`
- 质量标准：Quality Standard v1.0
- 审查流程：初稿审查 → 问题修正 → 发布前复审
- 参考基准：WHATWG URL Standard、WHATWG HTML Living Standard、MDN Web Docs

## 初稿审查结论

初稿结构完整，能够建立 URL、DNS、客户端/服务器、前端/后端和浏览器呈现的基础心智模型。内容对零基础学习者友好，并且多次强调“现象不是根因”，实战价值较高。

初审评分：**94/100**。

### 初审问题清单

1. 浏览器访问流程虽然已声明为简化模型，但还应更明确说明缓存命中可能减少网络访问，重定向可能增加请求轮次。
2. URL 示例中应补充 authority/userinfo 的课程边界，并提醒不要把账号密码写入 URL，避免学习者以为表中列出的是 URL 的全部可能组成。
3. HTML/CSS/JavaScript 示例需要实际组合运行验证，并在审查记录中保存验证结果。
4. MiniShop 页面观察记录缺少统一交付模板，不利于判断学习者是否完成实操。
5. 需要补充基础可访问性观察点，使“结构与语义”不只停留在一句说明。

## 专项检查

### 技术准确性

- URL 的 scheme、host、port、path、query、fragment 拆解正确。
- 已准确说明 fragment 通常不会随 HTTP 请求发送给服务器。
- 已避免把域名与 IP 描述为固定一对一关系。
- 已说明浏览器加载与渲染并非严格串行。
- 已避免仅凭页面现象判断前端或后端责任。

### 时效性

- 核心内容为稳定 Web 原理。
- URL 与 HTML 表述已对照 Living Standard。
- 未依赖具体浏览器版本或容易变化的 UI 操作。

### MiniShop 一致性

- 沿用商品列表、商品详情和购物车场景。
- 未新增冲突的数据库字段、订单状态或接口约定。
- 明确 MiniShop 为个人软件测试实践项目。

### 代码与安全

- HTML、CSS、JavaScript 均为基础示例，没有超出本章认知目标。
- 待将三段代码组合后进行语法和运行验证。
- 使用 `.test` 保留顶级域名作为教学地址，避免指向真实生产站点。
- 实操仅要求在 MiniShop 或获授权练习环境进行。
