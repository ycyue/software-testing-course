## 3. 专项裁决：第 7 章插在 03 和 04 之间，有没有帮我读 PRD？

官方说法（`docs/LEARNING.md` L27、`chapters/22-learning-path.md` L61）：

> 第 7 章 Web 基础插在分类之后、需求分析之前，为的是读 PRD 时知道页面从哪来。

### 第 7 章实际教了什么

URL 六段、DNS、客户端/服务器、前端/后端、HTML/CSS/JS、DOM。正文明确：**请求方法、状态码、Header、Body 留到第 9 章**。

### PRD 实际长什么样

`project/minishop/docs/PRD.md`「已确认规则」几乎是接口契约：

- `201` / `400` / `409`
- `token`、`Set-Cookie`、`HttpOnly`
- `Authorization: Bearer`
- `Body` **不含** `status`
- `SKU`、`qty=10/11`
- JSON API 在 `/api/`

第 7 章学完，这些格子我仍然不认识。

### 第 4 章有没有用上第 7 章

04A 前置知识只写「已完成第 1、2、3、7 章」。  
4.7「如何阅读 PRD」是五次业务阅读（目标、流程、规则、权限、可测试性），**不问 URL、不问 HTML、不叫我打开 `http://127.0.0.1:8765/`**。  
04B 真正让我做的是：对照「有验证码、密码 8～20」的教学草案和「无验证码、8～16」的 v1.0。那是双基线纪律，不是「页面从哪来」。

### 第 7 章真正帮到的、帮不到的

| 帮到 | 帮不到 |
| --- | --- |
| 知道页面不是「打开一个文件」 | 读懂 PRD 规则表里的 201/token/Bearer/SKU |
| 7-1 第一次要求 `python3 run.py serve`（此前只跑过临时 1-1） | 4.7 根本不走页面 |
| 前端/后端不要看见就判 | 开篇示例是 `https://shop.example.test:8443/products?...`，本机第一帧是登录/注册 |

### 裁决

**【Beginner Friction】插入动机善意，兑现失败。**  
第 7 章让我隐约知道「浏览器后面还有服务」，这和「读 PRD」不是同一件事。PRD 读不懂的主因是 **HTTP/JSON 契约语言提前出现**，而第 7 章故意不教这些。代价是：分类（第 3 章）和需求分析（第 4 章）被 655 行 Web 地图切开；按文件夹读的人会先读 04 再读 07，正式顺序的人读完 07 又要「倒回去」读 04。

建议桥（不改教材，只记在本报告）：见 §6 G07-0013。

## 5. `practice/run.py` 编号 vs 书面 2-1

本轮实跑（仓库根）：

```text
$ python3 practice/run.py 2-1
没有编号 2-1。先 python3 practice/run.py --list
完整清单（含 📖/🚧）见 practice/README.md。

$ python3 practice/run.py 3-1
没有编号 3-1。…

$ python3 practice/run.py 7-1
没有编号 7-1。…
```

`--list` 只印可运行 1-1/5-1/8-1/9-1/11-1/12-1/13-1/15-1/16-1/19-1，书面只提 4-1、6-1。

根 README 学习顺序表却给 **每一章**都挂了编号，2-1 / 3-1 / 7-1 / 10-1 / 14-1 / 17-1 / 18-1 / 20-1 / 21-1 / 22-1 和 1-1 排在同一列。警告写在表后引用块里：「不要对书面编号跑 `practice/run.py 2-1`」。零基础的操作是：昨天 1-1 能跑 → 今天照表敲 2-1 → 被说没有编号 → 以为自己仓库坏了或读错了章。

4-1 / 6-1 是书面，但脚本**认**这两个号（只打印「去写」）。2-1 / 3-1 / 7-1 同样是书面，脚本**不认**。同一套「X-1」三种待遇。

第 3 章正文还写「把卡片保存为 `exercises/chapter-03-classification-card.md`（实操 3-1）」，等于把我推向 `run.py 3-1`。

这是本课程最具体、可复现的挫败，不是抽象「体验不好」。

## 10. 本章结论（给总控）

零基础按正式顺序可以**起步**（1-1 能跑、公式能懂），但会在四处系统性迷路：

1. **入口**：文件名顺序 ≠ 学习顺序；`run.py` 编号 ≠ 书面 2-1。
2. **第 7 章插入**：付了 655 行和一次跳章的成本，没有换到「能读 PRD」。PRD 是接口契约；第 4 章也不使用 URL/HTML 阅读法。
3. **双基线与错误动词**：验证码草案、加入购物车、qty=11 当缺陷、空搜索图不像 Bug——都会让我交错作业。
4. **中后段过载 + 脚本代做**：11/15/08B/09/13 第一次读扛不住；绿灯实操不保证我会。

不建议判定「第 7 章插入完全错误」——「页面是一条观察通道」值得在需求分析前出现。建议判定：**当前插入形态对零基础是跳步+错位**，需要本机 URL、PRD 能读盒子、以及把 HTTP 词汇从第 4–5 章预期结果里拿掉。

体验总体：能跟着走，但会经常觉得「是不是我笨 / 是不是打开了错误的书」。那些感觉大多能在入口、图、作业尺子上消掉，不必重写 22 章。
