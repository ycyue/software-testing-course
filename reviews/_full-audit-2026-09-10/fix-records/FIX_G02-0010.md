原内容：（摘录）
```
**吞吐量**是单位时间内完成的工作量，例如每秒成功请求数。

教学计算：50 秒内成功 1000 次 → `1000 / 50 = 20` 次/秒。

吞吐高但错误率高，没有意义：每秒 1000 次全部 500，不是容量胜利。统计时应分开：**成功吞吐**和**错误率**。

示例：每次 100 ms 且每秒 20 次成功。
边界：错误请求不应算进成功吞吐。
```
修复后内容：（摘录）
```
**吞吐量**是单位时间内完成的请求数。JMeter Aggregate 报告里的 Throughput 列按**全部样本**计算，**含失败请求**，必须和 Error % 一起读。不要把这一列当成「每秒成功数」。

教学计算：50 秒内完成 1000 次请求 → `1000 / 50 = 20` 次/秒。若这 1000 次里有失败，JMeter 这一列仍把失败算进去。

吞吐高但错误率高，没有意义：每秒 1000 次全部 500，不是容量胜利。JMeter 的 Throughput 列这时仍然可能看起来很大，所以要和 Error % 一起读。缺陷和结论里分开写：**成功吞吐**和**错误率**。

示例：每次 100 ms 且每秒 20 次请求。
边界：JMeter Throughput 列含失败，必须和 Error % 一起读；缺陷里写成功吞吐，不要把全是 500 的吞吐当容量胜利。
```
为什么这样修：定义句先对齐 JMeter 列的算法（全部样本，含失败），再要求读 Error %、在缺陷里写成功吞吐。教学算术 `1000/50=20` 保留。未改 18.4 并发图、未改 `.jmx`。
依据：Apache JMeter User's Manual Glossary *Throughput*：number of requests / total time，含全部样本。Aggregate Report 的 Throughput 与 Error % 是两列，必须一起读。
是否影响其他章节：否。`ch18-tps-concurrency.html` 仍写「50 秒成功 1000 次」作为成功吞吐教学算式，不是 JMeter 列定义，本轮不改该图。
