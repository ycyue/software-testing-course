## 专项审查

### 技术准确性

- `NULL` 使用 `IS NULL`，`= NULL` 在审查中返回零行；
- `COUNT(*)`=3、`COUNT(display_name)`=2 与三名用户中一名显示名为空一致；
- `BETWEEN` 为闭区间，命中库存 3 与 5；
- `HAVING COUNT(*) > 1` 仅商品 1；
- INNER JOIN 对 Tester A 返回两行；LEFT JOIN 中无购物车的耳机 `qty` 为空，且一对多会复制左表行；
- SQLite 外键默认关闭已写明，需 `PRAGMA foreign_keys = ON`；
- 无 WHERE 的更新被明确禁止；`DROP`/`TRUNCATE` 未执行；
- 未教授 GET/POST 加密神话，未冻结订单状态。

### SQL 验证记录（SQLite 3.43.2）

| 语句意图 | 结果 |
| --- | --- |
| `WHERE phone = '13800138000'` | id=1 Tester A |
| `AND` / `OR` / `LIKE` / `IN` / `BETWEEN` | 与正文表一致 |
| `ORDER BY stock DESC LIMIT 2` | SKU-DEMO-001, SKU-DEMO-002 |
| `DISTINCT user_id` | 1, 2 |
| 聚合 | COUNT(*)=3, COUNT(display_name)=2, SUM(qty)=4, AVG(stock)=6.0, MIN=3, MAX=10 |
| `GROUP BY product_id` | 商品1 两行合计2；商品2 一行合计2 |
| `HAVING COUNT(*) > 1` | 仅 product_id=1 |
| INNER JOIN 用户 A | 鼠标 1/10，键盘 2/5 |
| `display_name = NULL` | 零行 |
| `IS NULL` | 用户 3 |
| `UPDATE stock=9` + `ROLLBACK` | 回滚后库存 10 |
| `DELETE id=2` + `ROLLBACK` | 行仍在 qty=2 |
| `UPDATE qty=11` + `ROLLBACK` | 事务内 11/10，回滚后 1/10 |
| `INSERT user_id=99`（外键开） | `FOREIGN KEY constraint failed` |
| `DROP`/`TRUNCATE` | 未执行 |

### MiniShop 一致性

- 教学库、SKU、手机号、库存规则均标明非正式 PRD；
- 未引入订单状态名；
- 超卖查询零行是教学数据状态，事务内 qty=11 标明为对照，不冒充项目缺陷。

### 安全

- 修改仅授权测试库；
- 先 SELECT、明确 WHERE、事务；
- 注入只作了解且禁止未授权攻击；
- 审查未连接生产。
