## 总判

读者跟得上：开篇 MiniShop「接口全绿、按钮点不动」把分层讲清，标明地图而非框架课，不要求 Playwright 套件；金字塔/ROI 有反例，也没有把第 16 章 pytest 判为过时。缺口：`LEARNING.md` 标了解即可，章内却大量 ⭐⭐⭐、「真正掌握」和 9/10 门槛；作业「四列各两条」里单元层几乎没有可抄例子；场景导入没有立刻托住刚会的 pytest。

## 阶梯

- 章内坡度：场景 → 级别 vs 分层 → 金字塔 → ROI 带场景，这条主线清楚。17.4 起才出现 Playwright / 报告 / CI，且标明不要求安装。但学习目标一次列出八条能力；17.5、17.8 又标 ⭐⭐⭐，夹在两段 ⭐⭐ 工具浏览之间，星级不是单调下降。总结「真正掌握七件事」+ 自测 9/10，把了解章写成了核心章门槛。
- 相对上一章：17 开篇承接「第 16 章已经能用 pytest + requests 写成可重复接口测试」，方向对。16B 预告只有一句章名，没有预先声明「下一章是地图、不是第二套框架」。17.2 / 17.8 把 pytest 放在金字塔中部、初级先站住的一层，**没有**把刚会的接口脚本说成不够用。风险在场景导入：先给「全绿仍点不动」，若不下锚，读者会以为要立刻补 UI 套件。
- 相对下一章：17 预告正确（CI 功能回归不是第 18 章负载模型），没有提前讲百分位/JMeter。18 开篇「第 17 章的 CI 能证明这次提交后功能脚本绿了」说得过满——读者在 17 只读到示例 YAML，并没有一条已绿流水线。
- 星级是否诚实：章头 ⭐⭐ 常用，与 `LEARNING.md` ⚪ 了解即可不一致。17.1 / 17.2 / 17.3 / 17.5 / 17.8 / 工作实战均 ⭐⭐⭐。了解章可以对「能口述金字塔和边界」要求高，但不该让人觉得必须掌握安装、报告生成和 CI 配置。

## 清晰

- 一句话核心是否真能当过滤器：能。「越靠近 UI 的观察越贵；分层是为了把钱花在值得重复的判定上。」可以用来否掉「ROI 永远最高」「每个按钮都录脚本」「金字塔 70/20/10」。17.3 对照表和错误 1、9 把 ROI 锁在场景上。
- 术语/例子问题：测试级别 vs 自动化分层拆得开；Cookie/Session/Token 明确不是金字塔三层；`goto /` 不是 `/login`。作业口令「按单元 / 接口 / UI / 手工**四列**」和模板「| 层 | 检查点 | … |」不是同一张表；单元层正文只有 `qty_allowed(11, 10)` 一条，读者刚学的是接口 pytest，编不出第二条纯函数检查。17.4 的 `pip install` + 可编译示例、17.6 的 pytest-html 命令，看起来像必做实验。
