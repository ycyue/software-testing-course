## 阶梯

- 章内坡度：开篇场景是对的（页面一句失败 → 上服务器），11.1～11.3 也该先站稳路径。之后变成无坡度命令目录：11.4 文件管理、11.9 `chmod`、11.11 `ssh`/`scp` 与核心技能平铺；11.5 才开始读日志，实操 11-1 要到 `:460`。练习 1～10 全是问答题，没有「改一条 grep 模式再看命中」。后半（面试/清单/门槛）并不更难，只是把 `rm -rf` / `kill -9` / `chmod 777` 再复述一遍。
- 相对上一章：承接合格。第 10 章末预告终端里用 `pwd`/`ls`/`grep`/`tail`/管道/`curl` 交叉验证，并交代 Copy as cURL 脱敏会沿用。本章 `:10` 接「浏览器里抓住登录请求」。未提前讲 DevTools 面板。
- 相对下一章：分寸合格。`:16` 写明与第 12 章并列、互不硬前置；预告只点 12A「先 SELECT 再改数」。12A 开篇同样写「Linux 不是硬前置」。11.13 点到第 13、14 章 Postman，没有把接口课讲完。
- 星级是否诚实：`chmod` 标 ⭐⭐ 是诚实的。`ssh`/`scp` 仍是 ⭐⭐⭐，和「没有远程机可写仅本机练习」打架；`kill -9` 虽写成反例，却进入学习目标、常见错误 3、自测门槛 4，读者会以为这是本章主技能。

## 清晰

- 一句话核心是否真能当过滤器：「日志、进程和磁盘是页面上看不到的观察通道」能当过滤器。正文中段（11.5～11.8、11.10、11.12～11.13）基本按这句话写。学习目标 12 条、常见错误前三条、自测门槛第 4 条把过滤器换成「别把机器搞炸」，核心被冲掉。
- 术语/例子问题：
  - **qty=11 口径（已修，本轮通过）：** 场景 `:44` 为 Network **400**、日志 **INFO** `inventory reject`；教学日志 `:210-213`、工作实战摘录 `:490-493`、练习 5/10 答案均与 `evidence/logs/app-sample.log`、`practice/11-log-grep` 一致。不要把 2026-09-09 的 500/ERROR 旧账再当成现行缺陷。
  - `:10` 仍用「日志里有没有 `ERROR`」当去服务器的理由，和场景「不要默认 `grep ERROR`」轻轻打架。
  - 11.6 警告段正确，但紧接着第一条可抄命令仍是 `grep ERROR app.log`（`:229`）。对着仓库样本会 0 命中。
  - macOS vs Linux 散落在 `:14`、`:88`、`:147`、`:353`、错误 5、练习 9，没有一张「本机先练这些 / 这些要 Linux」表。开篇 mermaid 第一步是 SSH，和后面 `cd project/minishop` 的本机路径两套故事。

### 4. 11.6 把 MiniShop 命令放第一条

- 目标文件：`chapters/11-linux.md`
- 位置：11.6 警告段后的命令块（`:226-232`）
- 拟写：

对着 MiniShop 仓库样本，先搜业务关键字，不要默认 ERROR：

    grep -n "inventory reject" evidence/logs/app-sample.log

命中行是 **INFO**，HTTP 是 **400**。`grep ERROR` 对这份样本是 0 行，不代表接口没拒。

一般排障（任意应用、非本仓库样本）才常用：

    grep -n ERROR app.log
    grep -E "ERROR|WARN" app.log
