## 总判

读完第 21 章的人跟得上：正式顺序与 README / LEARNING / 大纲同一条，没有第 23 章，也没有新的大型基础课。会绊住的是两套名字叠在 22.2～22.4（必须掌握 ≠ 第一梯队，高频使用 ≠ 第二梯队），开篇 mermaid 把 17、18 隐掉像另开一张路，结课自检模板空、没有启动命令，8～12 周没有给慢读者出口。

## 阶梯

- 章内坡度：开篇用「能列工具、讲不清库存/BUG-001」切入，先正式顺序再分档再入职后，最后自检，符合收束章。22.3～22.7 变成清单，坡度变平，但不比前半更难。
- 相对上一章：第 21 章预告「完整路线、必须/了解、入职后、官方资料」，本章兑现；开篇「走到简历怎么写」接得上。
- 相对下一章：明确无第 23 章，22.7 / 22.5 只指向入职后按团队栈补，没有把测开/性能提前讲成下章主课。
- 星级是否诚实：了解即可、后续方向标 ⭐⭐ 诚实。22.5 入职后、22.6 官方资料标 ⭐⭐⭐，读起来像结课前还要再学一门、收藏十五份规范。

## 清晰

- 一句话核心是否真能当过滤器：能。「先保住 MiniShop 主路径，再决定要不要加深自动化或性能」可以用来否掉「先学 Playwright / 生产压测」。
- 术语/例子问题：大纲三梯队（求职主线 / 能加分 / 了解即可）与章内三节（必须掌握 / 高频使用 / 了解即可）不是同一张表，图却插在 22.2 下。读者会把「高频使用」误认成第二梯队 Python/pytest；而 pytest 其实已经写进必须掌握并标明第二梯队。阶段测验 Q7 问的是「必须掌握 / 了解 / 入职后」三张表，正文却多出一张「高频」插在中间。MiniShop 规则（qty=10/11、无 status、BUG-001、非企业）与第 19～21 章一致，无新口径。

## 实操与图

- 实操类型与验收：书面 `exercises/chapter-22-self-check.md`（practice 22-1）。有路径、有五条必做、有完成标准（诚实的「不会」、五句无公司名/无状态机、90 天可执行）。但模板只有表头没有 22.2 的十行、没有 `python3 run.py serve/test`、没有「禁止抄 37 passed」、90 天没有正反例——读者无法判断自己有没有做完。练习 1～10 有对错，第 5、9、10 题能口头核。
- 现有图是否讲难点：`ch22-tiers` 三栏内容与 `COURSE_OUTLINE_v1.2` 第一/二/三梯队一致，命题「先保住 MiniShop」对。图注却去讲 Linux/SQL 并列和 01→07→04，那是顺序问题，不是这张三栏图在讲的事。开篇 mermaid 把 Linux+SQL 画成单节点、17/18 直接消失，和 22.1 正文「正式顺序仍含 17、18」打架。
- 缺图的概念（最多 3 个，要具体到节）：
  1. 22.1：正式学习顺序 vs 能力主链 vs 写作顺序（07 在 04 前、17/18 在顺序里不在主链）——现有 mermaid 没标出来。
  2. 22.2～22.4：必须掌握 / 高频使用 / 三梯队对照——可用表，不一定新图。
  3. 结课自检：不需要新图，把模板填成可抄作业即可。
