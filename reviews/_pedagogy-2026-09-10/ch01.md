## 清晰

- 一句话核心是否真能当过滤器：能。「测试 = 观察 + 判定 + 证据」后面真的在用：缺一块的反例、实操三臂、找 Bug 只是结果。读者可以用它判断「这算不算测试」。
- 术语/例子问题：
  - 1.1 把「草稿没写清空搜索」和「仓库已有 `R-SEARCH`、实现是 BUG-001」写在同一段，读者会问需求到底有没有写清。
  - 原则七在还没教 Verification / Validation 时，又用 Confirmation 去撇清第 2 章术语，免责声明比例子长。
  - 1.3 正文直接给三句定义，工厂类比只在图里；没看图的人看不到「类比 → 模型」。
  - MiniShop 在第 1 章首次出场，未写「个人软件测试实践项目」；阶段测验第 10 题考这句，只读本章会对不上。
  - 1.2 库存 9999 的人会犯错例子，立刻被「不要抄成 v1.0，鼠标是 10 件」打断。
  - 1.5 原则二点名「等价类、边界值」（第 5 章才教），读起来像现在就要会。

### 2. 拆开静态草稿和仓库 BUG-001

- 目标文件：`chapters/01-software-testing-intro.md`

- 拟写：

```
上面那种「运行起来再点」的活动是测试。静态测试是另一种：程序还没跑，你已经在读工作产品。

用两个分得清的例子，不要混成同一个故事：

- **静态、假设的草稿（不是仓库 PRD）：** 评审时发现「空白关键字该不该返回全量」一行都没写。你标出缺口，请产品补规则。这已经是测试。

```

### 4. 原则七只留「符合规格 ≠ 好用」

- 目标文件：`chapters/01-software-testing-intro.md`

- 拟写：

```
### 原则七：无缺陷谬论

即使系统完全按照需求实现，所有已知缺陷也被修复，用户仍然可能认为它不好用，或者不能解决真正的问题。

「符合规格」不等于「满足用户需要」。规格写「可以加购」，按钮却藏在三层菜单里，按规格会记通过，用户仍会流失。

```
