## 专项审查

### 技术准确性

- Cookie 作为 HTTP 状态管理机制，与 Session、Token 分层正确；
- Session ID 可以放在 Cookie 中，不被描述为 Cookie 的替代物；
- Bearer Token 按 RFC 6750 定位为出示方式，不与 JWT、OAuth、Session 等同；
- `SameSite` 未设置时按 `Lax` 处理、`None` 必须带 `Secure`，与 MDN 当前说明一致；
- 已避免“GET 不安全、POST 安全”；
- 前端约束验证可被绕过，关键规则需服务端生效；
- 横向/纵向越权区分正确，并限制在授权环境。

### 时效性

- Cookie 属性依据 MDN Guides（2026-09-08 核验）；
- 第三方 Cookie 限制只作功能排障提示，不展开 CHIPS；
- 不依赖易过时的 DevTools 按钮路径。

### MiniShop 一致性

- 测试环境沿用 `shop.example.test`；
- 购物车数量规则沿用第 4、6 章教学规则，并再次声明未冻结正式 PRD；
- 注册/登录阈值保持草案/教学模型；
- 未冻结订单状态、Cookie 名称、接口路径或 Token 字段。

### 代码与安全

- 教学登录表单为完整 HTML，经 Python 解析和 Chrome headless `--dump-dom`：标题、form、label/for、password、submit 均存在；无远程地址；提交被 `preventDefault` 拦住。
- 该验证只证明示例页面可打开并包含约定结构，不代表 MiniShop 登录已实现。
- 特殊字符、越权、类型绕过均限制在授权环境；缺陷中禁止粘贴密码和完整 Token。

### 初学者友好性

- 用“首页能打开”导入，后续失效具体；
- Cookie/Session/Token 用层次表和配合示例，而不是定义堆砌；
- 初稿对 HttpOnly 的解释不完整，会导致“Cookie 没了/不会发送”的误判。
