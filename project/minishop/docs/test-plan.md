# MiniShop v1.0 测试计划摘要

## 范围

PRD v1.0 已列功能，含注册、登录、商品、购物车数量、创建订单、管理员只读。不含支付、状态机、性能压测（第 18 章仅清单）、未授权环境。

## 策略

- 静态：对照 PRD / OpenAPI / 覆盖矩阵。
- 动态：Web 冒烟 + 接口（curl/Postman/pytest）+ 授权库 SQL + 日志。
- 自动化：`tests/` 中 pytest；空搜索用 xfail 跟踪 BUG-001。
- 性能：不做加压，见第 18 章清单。

## 优先级

P0：注册（合法/非法/占用）、登录、商品列表（pytest 覆盖，用例表不单列）、合法改数量（含 qty=10）、超库存 qty=11、创建订单、未认证 401。  
P1：四态输入、越权、管理员权限、空搜索。  
P2：页面表单结构、搜索命中。  
P0～P3 为课程**用例**优先级约定，不是缺陷等级，也不是全球标准。

## 入口

- `python3 run.py setup` 成功（或已安装 `requirements.txt`）
- `python3 run.py serve` 可打印 `MINISHOP_BASE_URL`
- PRD v1.0 已基线
- 教学账号可用

## 出口

本课程出口只写 **用例**优先级（P0～P3）和缺陷 **严重程度**（S1–S4 示例）。二者不是全球统一标准，不要把「P0 缺陷」写进同一句。

- 范围内 P0/P1 **用例**已执行，未执行项有原因
- 无未关闭的 **S1**，无未评估的 **S2**（BUG-001 按 S2 开放并写入剩余风险，不假装通过）
- 接口自动化与 `evidence/pytest-output.txt` 数字一致（当前目标：P0/P1 已写断言全部执行；空搜索为 xfail）
- 覆盖矩阵已填结果
- 测试报告已写
- 订单相关记录不含臆造状态名

## 风险

| 风险 | 应对 |
| --- | --- |
| 空搜索与 PRD 不符 | BUG-001 开放，不假装通过 |
| 单账号打满并发 | 不做性能结论 |
| 每次启动重置库 | 自动化使用独立临时库；手工证据在 `MINISHOP_RESET=1` 的一次性实例上采集 |
| Postman GUI 未点 | 集合入库；步骤写在第 14 章；不把 GUI 结果写进报告 |

## 环境

本机 `127.0.0.1`，SQLite，教学密码仅本地。一键命令见 `README.md`。
